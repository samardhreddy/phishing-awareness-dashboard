# Module 1 — Scope, Objectives & Ethical Boundaries

## Objectives

1. Measure how often employees **recognize and report** suspicious messages in a controlled simulation.
2. Quantify **susceptibility** (risky clicks / mock submits) without collecting real credentials.
3. Feed results into a **targeted awareness intervention** (Module 4), then re-measure.

## Scope

| In scope | Out of scope |
|----------|--------------|
| Synthetic / mock identities in a closed lab | Production mail systems without written approval |
| Aggregate metrics and dashboards | Public disclosure of individual failure lists |
| Awareness content and reporting workflow | Credential harvesting or malware delivery |
| Second-round simulation with a **different** benign scenario theme | Targeting people outside the approved roster |

## Target group

- Mock cohort: 20 synthetic employees across HR, Finance, IT, and Operations (see sample CSV).
- Roles are fictional; addresses use the `example.com` reserved domain.

## Ethical boundaries

1. **Authorization** — Written approval from the organization / course instructor before any send.
2. **Isolation** — Lab mail / simulation platform only; no forwarding to real external mailboxes.
3. **No secrets** — Landing interactions record an event flag only; never store passwords, OTPs, or MFA codes.
4. **Proportionality** — Messages must not induce panic (e.g., false legal threats about real people) or discriminate against protected groups.
5. **Transparency after the fact** — Debrief participants; explain how to report real phishing.
6. **Data minimization** — Retain only what is needed for grades/metrics; delete raw logs per course policy.
7. **Do no harm** — Provide a contact channel if someone feels targeted or distressed.

## Psychological principles (awareness framing only)

These principles appear in **real** social-engineering attacks and should be taught so staff can spot them — not used here to craft deceptive operational campaigns:

| Principle | What learners should notice |
|-----------|-----------------------------|
| Urgency | Artificial deadlines that skip verification |
| Authority | Spoofed executives or “IT Security” tone |
| Scarcity | “Last chance” or limited access claims |
| Familiarity | Lookalike brands, shared projects, known tools |
| Reciprocity / helpfulness | “Please confirm so we can help you” |

Classroom discussion should map each principle to **verification steps** (hover links, check ticket systems, call known numbers).

## Success criteria

- Delivery ≥ 95% in the lab export  
- Reporting rate improves after the intervention  
- Susceptibility rate decreases in round 2  
- Zero real credentials collected
